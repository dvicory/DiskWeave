# Milestone 9 verification record

## Claim boundary

This record supports the bounded operator-controlled recovery path as exercised at Milestone 9. It covers ordinary file-backed semantic behavior, SQLite adapter inspection/reopen behavior within its then-current evaluation claim, and one ARM64 Linux file-backed ublk publication run. It does not establish raw-device deployment, physical power-loss durability, production SQLite durability, broader frontend profiles, degraded read service, automatic repair, or P/Q recovery.
At that time, lost-custody recovery remained deliberately fail-closed: preview was diagnostic, and `recover apply` had no executable metadata-loss case because the C0a authority model had not yet been accepted. This record does not claim one.

The later C0a change is recorded separately in the archived post-gap authority-assessment OpenSpec change and current canonical requirement.

## Conservative boundaries

- Missing, corrupt/unreadable, unsupported, migration-required, and reconciliation-required recovery states remain distinct. Read-only inspection reports unresolved durable commit intent before manifest classification and does not compare prior/proposed state, initialize, migrate, reconcile, clean up, or expose a reconciled candidate. The archived closeout design's earlier observational-comparison wording is historical and superseded. Only a later writable open with ownership validates exact current-format prior/proposed state before initialization or migration; exact prior or proposed state is reconciled, while every other result remains reconciliation-required.
- Recovery preview is non-mutating. Apply reruns current identity, topology, recovery, and exhaustive verification checks, refuses stale proposals before mutation, and has no executable lost-custody case in the current authority model.
- Lost or corrupt commit acknowledgement authorizes no dependent mutation until reopen establishes exact prior or exact proposed durable semantic state; any other result remains reconciliation-required.
- A manifest carrying a mandatory newly calculated checksum-baseline obligation remains blocked after reopen while coverage is absent, partial, invalid, or unsupported. Only complete current persisted coverage satisfies that admission prerequisite.
- Service member selection and topology-derived publication identity use stable assignment semantics, not collection order; each publication assessment includes the member's complete current observation set.
- Linux live discovery distinguishes an exact current object, a stale or conflicting object for the same array, and an unrelated array before reporting publication state.
- Valid topologies outside the one-data/one-parity Linux publication profile are unsupported, not intrinsically invalid.
- Newly calculated checksums establish current coverage only; they do not prove historical correctness.
